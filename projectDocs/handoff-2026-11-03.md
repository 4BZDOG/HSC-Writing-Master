## 2. Rules this round set (keep to them)

**Live readiness is one number.** `utils/draftReadiness.ts` computes a raw `score` (internal only) and a
calibrated `percent` (0–100, a complete answer reaches 100). Every display reads only from `percent`:

- the meter's bar, figure and `aria-valuenow`;
- the Evaluate button's accessible name;
- the editor's `progress` veil.

The word (`level` → `label`) is `percent` in sixths. The colour (`chromaLevel`) is derived from the word,
capped at the question's target band. The top colour appears exactly when the word is "Ready to submit". Do
not add a second calibration or read `score` on a surface. The sweep in `tests/unit/draftReadiness.test.ts`
("word, number and colour agree") pins this. It is a completeness signal, never a band prediction.

**Light-theme colour comes from `--band-rgb`.** These light-only classes in `index.css` read `--band-rgb` from
the nearest ancestor, and fall back to slate when it is unset:

- `band-surface`, `band-surface-primary`, `band-header-strip`, `band-chip` (#463);
- `report-card`, `report-tile`, `edge-ink` (#465);
- `ai-wait-veil`, `ai-wait-card` (#464).

`--band-rgb` is set on the workspace, the prompt and writing cards, the navigator bar and the feedback and
improve modals. A new light surface should use these classes, not new `light:border-slate-*` literals. They
are light-only on purpose; dark mode was not changed this round.

**Contrast floors, measured not guessed:**

- text: 4.5:1 normal, 3:1 large;
- region boundaries (card, tile, divider, chip, tab and control edges): 3:1;
- control borders: slate-500 or stronger on white (slate-300 is 1.48:1, slate-400 is 2.56:1).

The light-theme sweep (`tests/e2e/light-theme.spec.ts`) now also measures text over gradient grounds in
every state, because the band tints are painted as background images.

## 4. Open items and decisions for you

1. **Readiness word on laptops.** At 1280–1535px wide, the footer hides the completeness word for space. A
   student sees the bar, % and colour, but not "Getting there". The visibility is set on
   `labelClassName` (`WorkspaceRightPanel.tsx`, `footerProgress`). Find room for it if wanted.
2. **"Ready to submit" ignores supporting terms.** It needs full length and every term the question names,
   but not the supporting terms. A draft can read "Ready to submit" with optional terms unused. This is a
   design call.
3. **Band 1–2 questions** stay red for most of the climb, because their palette has only one or two colours.
   This is expected; revisit only if students find it discouraging.
4. **Not browser-checked in #464:**
   - the feedback modal's "Regenerate" wait;
   - `GlobalLoadingOverlay`, which is shown only for syllabus-terms regeneration.

   Both share the card and veil classes that were checked. Give them a quick look in the app.

5. **The marking caret is remounted on every tick** (`AiWaitGlyph.tsx`, `key={tick}`) to replay its hop. It
   does not flicker. A cleaner design would move the caret out of the page's subtree, then drop the remount.
6. **The writing surface stays neutral in light mode** on purpose, so students don't write on a coloured
   page. A light tier tint is the obvious next step if more colour is wanted.
7. **CI pin.** `.github/workflows/build.yml` pins the E2E legs to `ubuntu-24.04`. When Playwright is
   upgraded to a release that supports Ubuntu 26.04, move the pin forward or back to `ubuntu-latest`.
   The browser cache key already includes the runner image.
8. **Stale design history.** `live-readiness-hint-plan.md` and `-verification.md` describe the pre-#460
   readiness model; each now opens with a note pointing here.

## 5. Working notes for the next session

- **Playwright in the dev container.** Playwright 1.58 looks for `chromium-1208`, but the container ships
  `chromium-1243`. Run e2e with:
  `PW_SERVERS=default PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome npx playwright test --project=chromium <spec>`.
  A standalone script needs
  `executablePath: '/opt/pw-browsers/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell'`.
- **ESLint inside a git worktree** (e.g. `.claude/worktrees/...`) skips files and looks for plugins in the
  parent checkout. Use `npx eslint --no-ignore --resolve-plugins-relative-to . <files>`.
- **`check:eager-reads` also fails on a plain alias** of an imported value at module top level
  (`const X = IMPORTED_CONSTANT`). Read it inside the component or function. CI's lint job runs
  `lint`, `format:check`, both type-checks, `check:eager-reads` and `check:dead-code`. Run all six before
  pushing.
- **The workspace opens a different first question from run to run**, so screenshots and contrast audits
  must pin a question to be comparable.
