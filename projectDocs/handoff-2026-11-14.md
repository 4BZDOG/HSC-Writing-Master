## 2. Rules this round set (keep to them)

**Drafts are merged across tabs; nothing else is.** A draft is `Prompt.userDraft` and
`draftElapsedSeconds`, inside the one `courses_data` value in IndexedDB.

- Every save goes through `saveCoursesMerged` (`utils/storageUtils.ts`). It reads a small revision
  (`courses_rev`) in the same transaction. If the revision is the one this tab last saw, it writes as
  before, with no extra read. If another tab has written since, it reads the stored library and runs
  `mergeForeignDrafts` (`utils/draftMerge.ts`): for each question, a draft this tab has **not** changed
  since its base takes the stored value; a draft this tab has changed keeps its own.
- The base is per tab (`draftBaseRef` in `hooks/useSyllabusData.ts`). A tab also pulls the other tab's
  drafts when it regains focus or becomes visible.
- **Known limits, by design:** library edits (topics, outcomes, renames) in two tabs are still last save
  wins, and so is typing into the same question in two tabs.
- A new per-question personal field must be added to `PERSONAL_PROMPT_FIELDS`
  (`utils/shippedCourseStamp.ts`), and to the draft merge if it should merge across tabs.

**A closing tab cannot rely on IndexedDB.** Chromium aborts a transaction started while the document
unloads; this was found by a real-browser test, after a unit test had passed. The final flush
(`pagehide`, `visibilitychange` to hidden, unmount) therefore does two things:

- `persistNow(recipe)` starts the IndexedDB write at once, which completes when the tab is only hidden;
- `stashPendingDraft` writes the draft synchronously to `localStorage` (`hsc.pendingDraft`, in
  `utils/pendingDraft.ts`).

At the next load the stash is applied only if the stored draft still equals the stash's `prev` (what
that tab last knew was stored). A later edit made elsewhere wins. The stash is cleared once a save holds
its text. Do not test unload durability by asserting a handler ran; use a real navigation
(`tests/e2e/draft-durability.spec.ts`).

**"Saved" must be true.** The writing footer shows "Not saved" whenever the last storage status is an
error (`draftSaveFailed`). Do not show "Saved" from React state alone.

**Exam Mode is a sitting, not a theme.**

- The clock is wall-clock time. It cannot be paused or reset; the controls are not rendered.
- The mode is kept in `sessionStorage` (`hsc.writingMode`, `utils/writingModeStore.ts`), so a reload
  returns to Exam in the same tab. It is restored only if the plan allows Exam.
- Aids are put away: the verb reference bar is not rendered (`utils/verbReferenceVisibility.ts`), and
  the question and scenario are printed without highlights, as the writing surface already was.
- The clock is always in view: `ExamClockChip` in the writing card's footer reads
  `utils/examClockStore.ts`, which the timer publishes to. **Do not lift per-second state into
  `Editor` or `WorkspaceRightPanel`**; use the external store.

**One figure per surface.** The band is stated once on the writing card, in its header. The footer is
three groups on one gap scale: words and saved state, then readiness (its word shown at every width),
then markings left and Evaluate.

**Header tools keep to one line.** Toolbar buttons are 32px on desktop and 44px on a phone. The
"Coach", "Exam" and "Focus" labels show only from `2xl`. Showing "Coach" from `xl` wrapped the tray at
1280 and 1400 and grew both card headers; `tests/e2e/workspace-chrome.spec.ts` pins the headers level
from 1280 to 1600.

**Focus Mode on a short desktop.** `FOCUS_SHORT` (`utils/cardChrome.ts`) is
`min-width: 1280px and max-height: 819px`. Under it, in Focus Mode only, both cards' headers, the
strategy strip and the footer compact, so the writing area shows seven ruled lines at 1280×720 and
1366×768. Tailwind needs each gated class written as a full literal string
(`FOCUS_SHORT_CLASSES`); do not build them by concatenation.

**The verb ribbon's overview is the staircase; its detail is the carousel.**

- The tier strip scrolls at every width. Centre padding lets tiers 1 and 6 sit in the middle. The
  selected tier is centred; with no verb, the strip opens on the tier 3 / 4 boundary.
- Focus by position is a progressive enhancement: the individual `scale` property on a `view()`
  timeline, behind `(hover: hover)`, `prefers-reduced-motion: no-preference` and `@supports`. Phones get
  none of it, and the "asks nothing of a phone" tests still hold.
- The pager browses and never selects. It is hidden from assistive technology, because the tier headers
  give a keyboard user the same movement (arrow keys, Home, End).

**Breadcrumb crumbs: short ones never shrink.** A label of 18 characters or fewer keeps its width. Longer
ones shrink to a floor (`--crumb-floor`, capped at 6em for an ancestor and 12em for the deepest). A fixed
min-width padded short names and was removed.

**Picker (Combobox) conventions.**

- A locked option is still a pick: pass `onDisabledPick` (the question picker opens the upgrade request).
- A toggle list passes `keepOpenOnSelect` and sets `selected` on each option.
- Menus open above the trigger when there is more room there, and scroll within
  `min(480px, 60% of the viewport)`.
- Use `role="group"` with `aria-pressed` for simple toggles. Do not use tab or toolbar roles without
  their keyboard model.

**After an `await`, do not write a path snapshot.** Use a functional update and check the reader is
still where they asked from (`selectPromptIfStillThere` in `utils/stateUtils.ts`; `placement.select`
in `PromptSelector`).

**Mark counts go through `marksLabel(n)`** (`utils/marksLabel.ts`): "1 mark", "3 marks".

## 3. How the work was checked

- **Per PR:**
  - `npm run test:all` (lint, unit, both type-checks, build and the chunk guards). The unit suite grew
    from 6,559 to 6,784 tests over the round;
  - the full Chromium e2e suite locally (83 passed, 7 skipped at #493);
  - CI green, including both Mobile Safari legs, before each merge.
- **Visual changes** were reviewed from before and after screenshots, at desktop widths from 1280 to
  1920, at 768 and 390, in both themes. Focus and Exam were also checked at 1280×720 and 1366×768.
- **Draft durability (#493)** has a real-browser spec with four tests. The two-tab and closing-tab tests
  were run against the old code first and failed there.
- **Regressions caught in review, before merge:**
  - #489: the breadcrumb's first shrink rule cut short names to "Cont…"; reworked so only long crumbs
    shrink.
  - #491: the scroll-driven animation never finishes, which hung an e2e helper that awaited
    `document.getAnimations()`. `settleTransitions` now waits only on `DocumentTimeline` animations.
  - #492: the "Coach" label wrapped the toolbar at 1280 and 1400 (see §2).
  - #493: the planned unload fix did not work in a browser (see §2); and `persistNow` could have replaced
    state with a copy that lacked a queued update, so it now applies its recipe on top.

## 4. Open items and decisions for you

1. **Exam Mode still marks.** Evaluate, Ctrl+Enter and "Use this version" (which writes the AI rewrite
   into the response) are available in Exam Mode, under a header that says "No assistance". Evaluate is
   how a sitting ends, so it was left. Decide whether "Use this version" and the rewrite belong in Exam.
2. **Copy-out is allowed in Exam Mode.** Paste and drop are refused; Copy is not.
3. **A curator's unsaved question edit is lost if Focus Mode is toggled mid-edit.** The question card is
   rendered in two different slots (`Workspace.tsx`, the `isFocusMode` branches), so the toggle remounts
   it. The shortcut is now blocked under an open dialog, but not while an inline editor is open.
4. **A cleared textarea, seen once.** During #493's e2e runs the response was cleared once just after a
   question opened. It did not recur in five traced runs and no cause was found. If it is reported, look
   first at the foreign-draft effect in `App.tsx` and the question-change effect in `Workspace.tsx`.
5. **Library edits in two tabs** are still last save wins (§2). A "changed in another tab" notice, or
   moving drafts into their own IndexedDB store, would close it; the second needs a `DB_VERSION` and
   `DATA_VERSION` bump with a migration.
6. **The localStorage fallback can say "Saved" falsely.** If IndexedDB is unavailable and the library is
   small enough to fit in `localStorage`, the footer reads "Saved" while loads prefer IndexedDB. The
   shipped library is too large for this to happen; a small custom one could.
7. **"N marks" with no singular** remains in about twenty places (`ManualPromptModal`,
   `SampleAnswerGeneratorModal`, `SampleAnswersAccordion`, `ProfileCharts`, `ReferenceMaterials` and
   others). `PromptSelector`'s question rows keep "Marks" in Title Case to match their neighbours.
8. **`CourseCreatorModal` uses tab roles without arrow keys** for Year 11 / Year 12, the same gap fixed
   in `ScenarioCarousel` and `MathSymbolToolbar`.
9. **Not checked in a browser:**
   - the verb ribbon's position scaling and the phone layouts were seen only in desktop Chromium, not on
     a phone browser (the Mobile Safari e2e legs pass);
   - Exam Mode surviving a reload (unit-tested; it depends on the plan being known at start-up);
   - the exam clock chip in the phone footer;
   - the ribbon's no-verb opening position (the app always has a verb once a question is open);
   - the picker menu's too-short-viewport fallback.
10. **Layout choices left as they are:**
    - Focus Mode keeps a 1024px column on very wide screens; lines already run about 124 characters.
    - At 1280px the collapsed breadcrumb still truncates the syllabus point while "3 marks | Band 2"
      sits beside it; at 768px the path scrolls.
    - At 1440×900 the question picker's menu opens upwards and covers the course, topic and sub-topic
      rows while open.
    - The selected verb is not shown in the collapsed ribbon bar on a phone; it clipped the title.
11. **Small leftovers:** the Coach-mode metrics dashboard still reads the debounced draft for a second
    after a question switch; `tests/unit/useSyllabusDataSaveFailure.test.tsx` and
    `.claude/skills/hsc-feature.md` were already unformatted before this round; the version in the
    headers of `DesignSpec.md` and `dataSpecifications.md` still reads v2.2.1.

## 5. Working notes for the next session

- **Playwright in the dev container.** As before:
  `PW_SERVERS=default PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome npx playwright test --project=chromium <spec>`.
  A standalone script needs
  `chromium.launch({ executablePath: '/opt/pw-browsers/chromium-1243/chrome-linux64/chrome' })`. Only
  the `chromium` project can launch here; phone projects (`Mobile Chrome`, Mobile Safari) run in CI only.
- **Mock logins** in the dev server: `user`, `teacher` and `admin`, each with its name as the password.
  `teacher` can enter Exam Mode; `user` gets the Plus upsell.
- **One dev server per port.** Playwright starts its own server on 3000. A second server, or a capture
  script that kills port 3000, breaks a running e2e suite with `ERR_CONNECTION_REFUSED`. Run capture
  scripts against another port (`npx vite --port 3200 --strictPort`, `BASE=http://localhost:3200`).
- **Screenshots while files are changing.** Capture "before" images from a separate worktree of main
  (`git worktree add --detach <dir> origin/main`, with `node_modules` symlinked), so edits in the main
  checkout do not hot-reload into the captures.
- **Two pages in one Playwright context share IndexedDB**, which is how the two-tab test works.
- **Full-page screenshots can move a horizontal scroller** in Chromium; make the viewport tall instead.
- **Sticky chrome covers element screenshots.** Scroll the target below the sticky header, or hide
  fixed and sticky elements for the capture.
- **The branch after a squash merge.** The merged branch and main have the same tree but different
  history. To continue on the same branch name without a force-push, join them with a merge commit that
  takes main's tree, then push normally.
- **Working with several agents in one checkout.** Give each a file-ownership list and tell it which
  regions of a shared file belong to another. Run the whole unit suite once, at the end. Commit only
  when every agent has reported.
