## 2. Before this reaches users

**Re-apply `supabase/schema.sql`** (idempotent; CI applies it twice). New or changed sections:

- §12 and §13: `schools` read policy and column grants (own school only; `id`, `name`, `plan_status`, `plan_period_end`,

- §29: `dispute` and `refund` incident kinds, and `resolve_billing_incident()`.
- §30: `school_seat_usage()`.

Until you re-apply it, "Mark resolved" and Seat economics say "Re-apply the database schema", and disputes are alerted but
not stored. The privacy narrowing (#369) is schema-only, so it takes effect only once the schema is applied; it does not
break members who are already signed in, because the plan columns they need stay readable.

**Stripe Dashboard**

- Webhook endpoint: add `charge.dispute.created`, `charge.dispute.closed` and `charge.refunded` (nine events in all).
- Each price: one flat recurring AUD price, with **tax behaviour** set to inclusive or exclusive. The app says "incl. GST"
  or "+ GST" from it and says nothing when it is unspecified.
- Customer portal: school staff can now open it and **can cancel the licence and change seats**. Check the settings, or see
  the owner decision below.
- Unchanged from 14 October: unpaid-invoice behaviour, ABN on the invoice template, and no `STRIPE_AUTOMATIC_TAX=true`
  until you have run one test-mode checkout.

**Environment**

- `BILLING_ALERT_WEBHOOK_URL` (optional, server-side): an incoming-webhook URL. Without it, nothing is sent.
- `VITE_AI_COST_PER_CALL_AUD` (optional, build time): total monthly AI spend divided by total monthly calls.
- **Every preview deployment that should receive Stripe events needs its own `STRIPE_WEBHOOK_SECRET`.** `vercel dev` needs
  one too (`stripe listen` prints it). A preview with none answers every Stripe event with 500.

**Check on a real preview (still the most important unverified item):** post an unsigned event to a preview URL and
confirm it answers 500. The fix and its tests run in process; nobody has seen it on Vercel.

## 3. Owner decisions

1. **Who can cancel a school licence.** Teachers and admins of a licensed school can open the school portal, and the
   portal allows cancellation and seat changes. Options: (a) accept it; (b) admins only; (c) a second Stripe portal
   configuration for teachers with cancellation off (`billingPortal.sessions.create` takes `configuration`). Built as (a)
   because teachers can already buy a licence.
2. **The cost question.** Open Billing overview → Seat economics after a few weeks of real use, set
   `VITE_AI_COST_PER_CALL_AUD`, and read the verdicts. `projectDocs/seat-economics.md` sets out the three options (pooled
   school allowance, a lower per-seat cap, a higher seat price) and the data that would justify each.
3. **Disputes and refunds stay manual.** A lost dispute or a full refund does not end the licence; the alert says so.

## 4. Still open, in priority order

**Money and security**

- Unsigned-event handling is fixed for the webhook only. `api/_lib/auth.ts` `isMisconfigured()` keys on
  `NODE_ENV === 'production'`, so a preview with half its Supabase variables may serve the AI proxy openly; and
  `isStripeMisconfigured()` plus the mock-URL fallbacks key on `isProductionRuntime()`, so a preview with prices but no
  secret key gives the upgrade button a mock URL (no plan is granted). Move `isDeployedRuntime()` to a dependency-free
  module (for example `api/_lib/runtime.ts`) and use it in all three.
- Finding 34 (P1): two members of one school can each hold an open licence checkout; detection is after payment.
- Findings 25, 35, 37: a seat reduction below the member count is not enforced; a transient Stripe failure when expiring a
  displaced checkout leaves it open for up to 36 minutes; a teacher with a personal Plus and an invoiced licence is flagged
  as a duplicate.
- Privacy, left over from #369: any teacher can read Stripe event ids (`Reviewers read stripe events`) and every user's AI
  usage (`get_ai_usage_report`, `get_ai_model_usage_report`), and can read their students' `stripe_customer_id` through
  `profiles_read`. The superseded `list_schools()` definitions in §12 and §13 can be deleted.
- `recordIncident`'s duplicate path rewrites the open row's detail and `subscription_ids`; two disputes arriving at once
  for one account can drop an id from the row (the alert still goes).
- A cancelled licence keeps its `stripe_subscription_id`, so the school portal still opens for a school whose licence has
  ended. Consider requiring `schoolHoldsLiveLicence`.

**Purchase orders and billing** (from 14 October, unchanged): the payment banner's overdue wording is card-specific; an
approved request hides the form after the licence lapses; no due-date column; a requester cannot withdraw; near-simultaneous
approvals; Australia only; the admin approval call has no fetch timeout; working days ignore NSW public holidays; two copies
of the invoice-enabled switch. `SeatOverageNotice` still tells non-purchasers to ask the buyer (a test pins that).

**Prices:** the "Save 38%" line (`VITE_PLUS_YEARLY_NOTE`) is still typed by hand; the School seat copy assumes a yearly price
(the interval is read but not checked); "No daily limit" for paid plans is still wording to confirm against the 300-call

**Seat economics:** membership in the report is today's, not at the time of each call; per-model cost would be more

**UI and tests (from 14 October, unchanged):** tap targets under 44px in several admin and syllabus screens; contrast items;
the 7.6 MB IndexedDB re-save on every boot; unit files that time out at 5 s under load but pass alone (this round the set was
different on each run: verb ribbon, navigator feedback, content audit, check-script verdict, plan card period end).
`docs/` is outside `format:check`.

## 5. Lessons worth keeping

- **A column grant needs a search for every way the client reads the table.** The first version of #369 granted only
  `id, name` on `schools` and its search missed the alias form `school:school_id (…)` in `services/authService.ts`. That
  read is a "soft query", so the failure would have been silent: every school member would have lost their School plan. A
  review caught it; the privacy test now runs the exact sign-in query and the static test detects every embed form.
- **A rate limit can stop a worker mid-task.** Two workers died on a weekly model limit with their work uncommitted. The
  work was recoverable because it was in their worktrees. Ask a worker to commit early.
- Workers' ESLint fails inside `.claude/worktrees/` (a second copy of the prettier plugin is found); run it with
  `--no-ignore --resolve-plugins-relative-to .`.
- Branches that both edit `components/SchoolLicencePanel.tsx` or `supabase/schema.sql` end up conflicting at the end of the
  file. Resolution is always "keep both", but expect it, and merge the schema PRs one at a time.
