## 3. Behaviour changes you get with no configuration

- A second School licence for a school that already has one is refused before payment (409).
- A checkout whose account lookup fails returns 503 instead of proceeding.
- Checkout sessions expire 31 to 36 minutes after creation (was 24 hours); pressing Upgrade again expires the earlier page.
  If the earlier page was already paid, the new purchase is refused and the customer is charged once.
- A webhook redelivery that arrives while the first is still running gets 409; a delivery may briefly show as failed in Stripe.
- Every return to a signed-in tab (at most every five minutes) re-reads the session; a licence going live or lapsing reaches
  members within about five minutes. This adds profile writes.
- The plan unlocks on return from checkout. The webhook is still required for renewals, cancellations, failed payments and seats.
- A deployment with Plus prices but no `STRIPE_SECRET_KEY` shows "Checkout is unavailable right now, so you have not been charged".
  A deployment with no Plus price no longer shows "Keep me posted".
- **#355 (teachers):** the Class report PDF locks unless the teacher's school holds a licence; a teacher not attached to a
  school sees "Ask an admin to add you to your school" and a copy-a-note button instead of "Buy N seats" (and no mailto enquiry);
  a teacher in a licensed school sees "your school already has a licence" instead of a seat picker.
  Students no longer see a School enquiry link.

## 7. Lessons worth keeping

- WebKit and Mobile Safari clicks are slow on a loaded runner: never bound a helper action that runs on WebKit under 30 s.
- A settled read does not help when a CSS transition is frozen; disable transitions in the test.
- Do not extrapolate E2E speed-ups from a local run: per-shard fixed costs decide it on CI (both experiments lost for that reason).
- A merge push cancels the PR's in-flight run, and the cancelled run reports a failed "E2E Tests" gate; check the current head before reacting.
- Tests that read the clock twice (fixture then expectation) fail about one run in a few hundred; read it once.
- Every PR here appended to the same change-log and review-doc spots, so merging one conflicted the next; the resolution is always "keep both", but expect it.
